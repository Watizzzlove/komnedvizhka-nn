# Дизайн-документ: Прототип маркетплейса коммерческой недвижимости Нижнего Новгорода («КомНедвижка НН»)

**Дата:** 11 ноября 2026 г.  
**Статус:** На согласовании (Draft)  
**Проект:** Прототип маркетплейса коммерческой недвижимости (MVP витрины + мультиисточниковая агрегация)

---

## 1. Контекст и Цели (Intent & Why)

### 1.1. Зачем создается проект
В Нижнем Новгороде рынок коммерческой недвижимости фрагментирован: объявления разбросаны между Авито, Циан, местным порталом GiperNN, сайтами агентств («Монолит», «Чекни» и др.) и закрытыми риелторскими базами. Для арендаторов и инвесторов нет единой точки входа с удобными профильными фильтрами (высота потолков, пандусы, кран-балки, класс офиса, электрическая мощность, первая линия, близость к метро).

### 1.2. Цель прототипа
Создать полноценный работающий прототип платформы, который:
1. Демонстрирует клиенту интерфейс уровня топовых B2B-классифайдов: строгий, современный дизайн без синих градиентов и стоковых штампов.
2. Включает интерактивную карту Нижнего Новгорода с кластеризацией, фильтром по районам и станциям Нижегородского метрополитена.
3. Содержит каталог коммерческой недвижимости с динамическими фильтрами под каждый тип объекта (офисы, склады, торговля, производство, участки).
4. Демонстрирует реальную агрегацию данных из нескольких источников:
   - **GiperNN** (главный профильный нижегородский портал).
   - **Домклик API** (коммерческая недвижимость в координатах НН).
   - **XML-фид в формате Яндекс.Недвижимость** (стандарт брокерских агентств).
5. Позволяет синхронизировать данные по кнопке из панели управления и показывает дедупликацию объектов.

### 1.3. Non-Goals (что осознанно исключено из прототипа)
* **Онлайн-сделки с ЭЦП и безопасные расчеты:** в реальной коммерческой недвижимости сделки закрываются офлайн с юристами; сложная автоматизация на стадии прототипа нецелесообразна.
* **Сложный биллинг и эквайринг (54-ФЗ):** заменяется демонстрационными статусами тарифов («Базовый», «Продвижение», «Топ»).
* **SMS-верификация через реальный шлюз:** для прототипа используется симуляция быстрого входа по коду.

## 2. Архитектурный подход (Selected Approach)

Выбран **Гибридный подход (Монорепозиторий Next.js + Python CLI воркеры с единой БД SQLite)**:
* **Фронтенд и API:** Next.js (App Router, React, Tailwind CSS, Lucide Icons).
* **База данных:** SQLite (локальный файл `marketplace.db`), обеспечивающий запуск в одну команду без развертывания СУБД.
* **Картография:** Интерактивная карта (Leaflet / Яндекс Карты) со слоями кластеризации и станций метро НН.
* **Скрейпинг и сбор данных:** Модульные скрипты в `/scrapers` (Python с `httpx`, `beautifulsoup4`) + встроенный сидер реальных объектов для мгновенного запуска витрины без задержек.

## 3. Спецификация модели данных (Canonical Property Schema)

Каждый объект в системе нормализуется к единому интерфейсу `Property`:

```typescript
export type PropertyCategory = 
  | 'office'          // Офисы
  | 'warehouse'       // Склады
  | 'retail'          // Торговые помещения / стрит-ритейл
  | 'manufacturing'   // Производственные площади
  | 'land'            // Коммерческая земля
  | 'free_purpose';   // Помещения свободного назначения (ПСН)

export type DealType = 'rent' | 'sale' | 'sublease';

export interface Property {
  id: string;
  title: string;
  description: string;
  dealType: DealType;
  category: PropertyCategory;
  priceTotal: number;           // Руб. (в месяц для аренды, полная для продажи)
  pricePerSqm: number;          // Руб. за м²
  area: number;                 // Общая площадь в м²
  address: string;              // Полный адрес в НН/области
  district: string;             // Район (Нижегородский, Советский, Автозаводский и др.)
  metroStation?: string;        // Ближайшая станция метро (Горьковская, Стрелка и т.д.)
  metroDistanceMin?: number;    // Время до метро пешком/транспортом
  coordinates: {
    lat: number;
    lng: number;
  };
  photos: string[];
  sourceName: 'GiperNN' | 'Domclick' | 'XML-Feed' | 'Direct';
  sourceUrl?: string;
  verifiedOwner: boolean;       // Флаг «Проверено собственником»
  
  // Специфичные динамические характеристики (JSON)
  features: {
    // Склад / Производство
    ceilingHeight?: number;     // Высота потолков (м)
    floorType?: string;         // Антипыль, бетон, асфальт
    hasRamp?: boolean;          // Пандус / дебаркадер
    hasRailway?: boolean;       // Ж/Д ветка
    powerKw?: number;           // Выделенная мощность, кВт
    hasCraneBeam?: boolean;     // Кран-балка
    craneTonnage?: number;      // Грузоподъемность крана, тонн
    heating?: boolean;          // Отапливаемый / холодный
    
    // Офис
    buildingClass?: 'A' | 'B+' | 'B' | 'C';
    parkingSpaces?: number;     // Парковочные места
    floor?: number;             // Этаж
    totalFloors?: number;       // Этажность здания
    hasVentilation?: boolean;   // Приточно-вытяжная вентиляция
    
    // Ритейл / Общепит
    line?: 1 | 2;               // 1-я или 2-я линия
    separateEntrance?: boolean; // Отдельный вход с улицы
    displayWindows?: boolean;   // Витринные окна
    wetPoints?: number;         // Количество мокрых точек
    exhaustVent?: boolean;      // Отдельная вытяжка под общепит
    
    // Земля
    landCategory?: string;      // Категория земель
    permittedUse?: string;      // ВРИ (вид разрешенного использования)
    gasConnected?: boolean;     // Газификация
    waterConnected?: boolean;   // Водоснабжение
  };
  
  createdAt: string;
  updatedAt: string;
}
```

## 4. Архитектура интерфейса (UI / UX)

### 4.1. Визуальный стиль
* Строгий, технологичный B2B-стиль: нейтральная графитовая палитра (Slate/Zinc), теплые акцентные цвета (янтарь/медь вместо заезженного синего), высокая плотность информации, читаемая типографика.

### 4.2. Ключевые экраны и компоненты
1. **Шапка (Header):**
   - Логотип сервиса («КомНедвижка НН» / «ОбъектНН»).
   - Переключатель сделки: «Аренда» / «Продажа».
   - Кнопка статуса агрегации: «Синхронизация данных» с индикатором статуса источников.
   - Размещение объявления / Вход в демо-кабинет.
2. **Панель фильтров:**
   - Быстрый выбор категории (табы: Все, Склады, Офисы, Ритейл, Производство, Участки).
   - Фильтры первого уровня: Район НН, Ближайшее метро, Цена (от/до), Площадь (от/до).
   - Динамические фильтры (разворачиваются при выборе конкретной категории):
     - При выборе «Склады»: ползунок высоты потолка, чекбоксы «Пандус», «Отопление», «Ж/Д ветка», мощность от N кВт.
     - При выборе «Офисы»: класс A/B, этаж, парковка.
     - При выборе «Торговля»: 1-я линия, отдельный вход, витрины.
   - Сортировка: «Сначала проверенные», «По цене (возр/убыв)», «По площади».
3. **Витрина объектов (Переключение Каталог / Карта):**
   - Режим **«Список + Карта»** (Split view): слева карточки объектов, справа интерактивная карта с привязкой к видимой области.
   - Карта поддерживает кластеры, кастомные метки по типам помещений, всплывающие балуны с мини-карточкой и подсветку линий метро НН.
4. **Карточка объекта (Modal / Страница):**
   - Галерея фото с зумом.
   - Бейджи: Категория, Источник (GiperNN / Домклик / Фид), «Проверено».
   - Блок расчета цены: крупно ставка в месяц и автоматический пересчет за м²/год и м²/мес.
   - Таблица характеристик с акцентом на ключевые параметры (мощность, потолки, класс).
   - Форма мгновенной заявки на просмотр («Записаться на просмотр на дату/время»).
5. **Панель управления источниками (Data Aggregation Drawer / Modal):**
   - Сводка по источникам: GiperNN (активен), Домклик API (активен), XML-фид (активен).
   - Кнопка ручного запуска сбора объектов.
   - Статистика дедупликации: «Всего получено: X, Склеены дубли: Y, Опубликовано: Z».

## 5. Интеграция скраперов и дедупликация

### 5.1. Источники
1. **GiperNN Scraper (`scrapers/gipernn.py`):** извлечение коммерческих предложений по Нижнему Новгороду.
2. **Domclick Connector (`scrapers/domclick.py`):** запросы к гео-эндпоинтам Домклика в границах Нижнего Новгорода.
3. **XML Feed Ingest (`scrapers/xml_feed.py` / TS-парсер):** чтение стандартного XML-фида в формате Яндекс.Недвижимость.

### 5.2. Алгоритм дедупликации (Deduplication Pipeline)
* Объект считается дублем, если:
  1. Нормализованный адрес совпадает (или расстояние между координатами < 80 метров);
  2. Разница в площади менее 3%;
  3. Тип сделки и категория совпадают.
* При обнаружении дубля сохраняется объявление с более полной карточкой (больше фото, подробнее описание), а второй источник добавляется в список ссылок объекта.

## 6. План проверки и верификации (Verification Plan)

1. **Работоспособность UI:** Проверка всех типов недвижимости, переключения фильтров, адаптивности под мобильные экраны.
2. **Картография:** Корректное отображение меток в границах Нижнего Новгорода, работа кластеризатора и зума при клике на станцию метро.
3. **Агрегация:** Прогон сидеров и скраперов, заполнение базы объектами из всех трёх заявленных источников.
4. **Перформанс:** Мгновенная фильтрация на клиенте и отклик страницы до 500 мс.
